## 六、流程

```bash
docs/book-v2-pipeline.sh full   NN "檔名標題" "章卡名稱" "<目標字數>"   # 寫作→讀者→編輯→潤飾→稽核
docs/book-v2-pipeline.sh expand NN ...                                  # 以現稿為底展開場景
docs/book-v2-pipeline.sh review NN ...                                  # 作者改過結構後重跑後四步，不重寫
docs/book-v2-pipeline.sh audit  NN "檔名標題" "章卡名稱"                 # 只跑一致性稽核
```

- 每一步都是全新的 `codex exec` session（`gpt-5.6-sol`，high），每步限時 30 分鐘。log 在 `~/.cache/book-v2-logs/`。
- Codex 額度用完時，可改用 Claude subagent 跑同樣的步驟，prompt 要自己帶上 skill 與偏好的路徑。
- **後記的 commit 刻意不含 `hand edit`**：`14-後記.md` 是第一次入庫，diff 裡每一行都是新增行，帶了標記會把整篇凍成「原樣保留」。它的作者手改句清單維護在 `~/.cache/book-v2-logs/14-extra-author.txt`（21 句），要重跑後記時用 `EXTRA_AUTHOR` 帶進去。清單只放作者真正手改或親自挑選的句子，見修稿偏好第 40 條。
- **第十三章的作者手改句清單已被 `8d650f0` 過度凍結**：該 commit 訊息含 `hand edit`，但它同時帶進本輪新寫的七月三十一日與收碗兩場，所以腳本會把第十三章所有新增行都當成作者手改句。若之後要對第十三章再跑 `review`／`audit`，改用 `EXTRA_AUTHOR` 指定真正的九句手改（見 `13-scenes.md` 末段），不要依賴自動抽取的清單。
- **`expand` 會整章展開**。只想改某一段時不要用它，改成自己寫 prompt 指定範圍。
- 作者手改句：腳本從含 `hand edit` 的 commit 取**新增行**；還沒 commit 的用 `EXTRA_AUTHOR` 指一個每行一句的檔案帶進去。
- **一個檔案第一次入庫時不要在 commit 訊息寫 `hand edit`**。新檔案的 diff 裡每一行都是新增行，會把整章凍成「原樣保留、不直接改」，之後的 `review`／`polish`／`audit` 連事實矛盾都不能動。第七章就是這個情況，所以它的定稿 commit 沒有這個標記；要保護特定句子改用 `EXTRA_AUTHOR`。

## 七、兩輪已寫進規則的問題

### 第一輪：旁白結論句（2026-09-20）

**問題**：「寫完一幕，再用一句說明它的意思」反覆出現，刪掉幾句就長出新的幾句。原因是那是模型的預設收尾方式，點名刪除只會產生替代品。

**處理**：skill 新增「命名與金句」一節，核心是代價測試——**這句話說出來，說話的人損失了什麼**；底下的「收束檢查」是每一場寫完後看最後一句，**刪掉場景若仍成立就刪掉**。稽核機械檢查加了第 g 項（標記每一場與每一段的最後一句是畫面、動作、對白還是結論），潤飾同檢查。來源是 `docs/日劇金句脈絡-冬のなんかさ春のなんかね.md`。

### 第二輪：流水帳（2026-09-21）

**問題**：整章讀起來平。兩種形狀——（一）把完成一件事的步驟寫齊：移動、開關、拿取、收納、填表、付款；（二）連著幾段確認同一個狀態或同一份親密，每段都有畫面，人物卻沒有往前走。

**處理**：判準是**這一段之後，有沒有人知道了新的事，或失去了什麼**；沒有就刪，一種處境留一個最完整的例子。寫進 skill 的「流水帳檢查」、偏好第 34 條、稽核機械檢查第 h 項與潤飾檢查。

## 八、規則重點

- **書稿等作者校閱同意才 commit**；提交時逐一指定檔案，**不要用 `git add -A`**。
- 作者手改句原樣保留；與事實衝突時列進「留給作者決定」，不直接改。
- 修稿偏好 38 條在 `docs/book-v2-workflow.md`，寫作與潤飾都適用。重點：不用真實店名、不把潛台詞說白、一個時刻一個細節、用字求準、不放事後評價與主題句、熟悉的感受不再拆解、寧可刪贅詞不為字數補句、例子少而完整、流水帳兩型、不替自己的行為命名、一段一件事、男主角不習慣性反駁、保留有根的隱喻。
- 正文不寫年份數字；句尾原則上不留標點；不使用破折號；貓叫黑糖，代名詞用「牠」。
- 流程腳本、章節腳本與文件的修改照常直接 commit。
