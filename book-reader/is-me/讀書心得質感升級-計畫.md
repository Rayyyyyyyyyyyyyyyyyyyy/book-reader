# 讀書心得「質感」升級計畫

更新日期：2026-09-29

用途：針對一本書進行討論，沿著作者在意的問題延伸相關觀念，再把討論中形成的理解寫成讀書心得。

質感來自討論的內容：哪個觀點讓人停下來、為什麼同意或不認同、它如何解釋生活，又在哪裡不夠。文字需要有 Rui-Xuan 的聲音，也要保留這些思考如何往前走的過程。

## 1. 每次從一本書開始

起點可以是書名、段落、一個概念、讀後感，或已經寫了一部分的心得。不要求先提供完整筆記，也不要求先更新整份人設。

先辨認這次想談什麼：

- 書中哪個說法最有感、最困惑，或最想反駁。
- 原本怎麼理解，讀到這裡後什麼開始改變。
- 想理解書本身，還是已經有一個想往外追的問題。

只有書名時，先介紹足以展開討論的核心問題與觀點，讓作者有地方接話；已有具體感想時，直接從那裡往下談。書目或原文不明、且會影響判斷時，再釐清必要資訊。

## 2. 討論如何往下走

以 [ai-reader](../../.agents/skills/ai-reader/SKILL.md) 的陪讀討論分支協助理解，先回應當下的疑問，再補背景、例子或下一個值得追的問題。以下是可往返的方向，不是每次都要跑完的問卷：

| 討論方向 | 要做的事 | 能帶來的下一層理解 |
|---|---|---|
| 釐清主張 | 分清書中說法、作者自己的理解與延伸 | 我們現在同意或反對的，究竟是哪一句話 |
| 追問機制 | 說明事情為什麼會這樣，辨認中間的因果與條件 | 這個概念如何運作，而不只知道它的名字 |
| 檢查邊界 | 看研究依據、例外、反例與環境限制 | 哪些情況適用，哪些情況不能照搬 |
| 接回生活 | 用作者提供的經驗，或明確標示的一般情境檢視觀點 | 理論放進生活後，多了什麼矛盾、代價或選擇 |
| 延伸觀念 | 引入能回答當前問題的相關概念或其他書 | 原本的理解被補足、挑戰，或需要重新定義 |
| 回看起點 | 對照最初的感想與現在的理解 | 什麼仍成立、什麼改變，還有哪些地方不知道 |

不只附和，也不為反對而反對。理解有偏差時指出落差與依據；理解成立時，補上它還沒處理的條件。先給有內容的回應，再追問最值得繼續的一點，不把思考全部丟回作者。

討論可以暫時往旁邊走，但要說清楚這條支線與原來的問題有什麼關係。遇到有價值的新方向就繼續追；不為維持大綱而打斷，也不把每回合都收成全書摘要。

## 3. 延伸相對應的觀念與討論

延伸的出發點是當前問題。可以往心理機制、人際關係、行為選擇、工作與生活條件、價值取捨或相反觀點走，取決於這本書與作者實際談到什麼。

引入一個觀念時，至少要說清楚它增加了什麼：

- 解釋原本只看見結果、還不清楚的機制。
- 回答書中留下、討論中冒出的問題。
- 提供反例或相反角度，讓過於乾淨的結論變複雜。
- 讓兩個看似相似的概念分得更清楚。
- 幫助作者重新看待一段經驗或一個選擇。

不以多提幾個術語、書名或名人證明討論深入。需要研究、原文或引述時查核來源；分清研究結果、故事案例、價值判斷與我們的推論，資訊不足就保留不確定。

討論時可以探索多條關聯，不預設作者讀過延伸的書。寫成一篇心得時，再依 [structure-and-revision.md](../../.agents/skills/rui-xuan-book-v2/references/structure-and-revision.md) 收斂有作用的連結，一篇最多牽兩本，沒有必要也可以不牽。

### 例：從《人生4千個禮拜》的議題往下談

依 [既有心得稿](../讀書心得/人生4千個禮拜.md) 中「效率提高後，省下的時間留給誰」這個問題，可以繼續追：

1. 工作完成得更快，為什麼仍可能更忙？工具省下時間之後，還有哪些要求與選擇在作用？
2. 把所有空檔都視為可以接事的餘裕，背後是個人習慣，還是工作環境也在鼓勵這件事？
3. 休息是否一定要先證明有助於效率？如果不必，安排時間的標準會怎麼改變？
4. 想把握有限的人生，會不會又把體驗變成另一張清單？如何區分想親自經歷與不想漏掉任何可能？

這是沿著現有稿件問題延伸的示範，不是替每本書預設相同答案。最後留下哪些方向，要看實際討論中哪一層讓作者的理解發生變化。

## 4. 人設、生命素材與既有心得怎麼用

這些材料提供背景、例子與思考線索，按當次問題取用。一本書的討論不以補齊個人近況、核實所有人生日期或完成素材表更新為前置作業。

| 材料 | 在討論與寫作中的作用 | 取用界線 |
|---|---|---|
| [Rui-Xuan.md](Rui-Xuan.md) | 理解既有觀察、重視的事、內在矛盾與生命歷程 | 屬過往材料的分析，不替作者決定現在怎麼想，也不把人物特徵機械套到每本書 |
| [Rui-Xuan-生命素材.md](Rui-Xuan-生命素材.md) | 抽象概念需要落地時，找有根據的經歷、觀察或比喻 | 只拿本篇需要的部分；示例句不是作者逐字自述，不強迫每篇加入私人故事 |
| [story-base.txt](story-base.txt) | 討論涉及某段原始回憶時，補讀事件脈絡 | 不從書稿創作回填事實，不為了例子漂亮而補未提供的經歷 |
| [既有讀書心得](../讀書心得/) | 找作者先前怎麼理解相關概念，辨認呼應、差異或後來的修正 | 依問題讀相關稿，不每次讀全部；不把模型整理的所有結論都當成作者已採納 |

新近況與新的經歷可在討論中自然補充。只有它影響當前理解或值得長期保留時，才整理回人物資料或生命素材；不把每次讀書討論都變成生命材料盤點。

## 5. 從討論走到讀書心得

陪讀時先把問題談清楚。作者要求寫、改寫或整理成心得時，使用 [rui-xuan-book-v2](../../.agents/skills/rui-xuan-book-v2/SKILL.md)，在既有授權內直接動筆；不再重問一次是否要寫，也不必等所有支線都有答案。

動筆前，從對話裡找出：

- 這篇真正想追的問題，以及值得保留的起點。
- 作者已表達的感受、判斷與自我修正。
- 書中觀點、延伸概念、生活材料各自負責哪一層理解。
- 哪些支線只是探索，哪些已經成為文章的一部分。
- 還不能說成確定結論的部分。

按照 [book-review.md](../../.agents/skills/rui-xuan-book-v2/references/book-review.md) 組織理解的推進：從具體疑問進去，讓後一段從前一段長出來，最後停在更準確的理解、行動或生活畫面。文章可以包含反對、困惑與未完成的思考，不必做成讀完之後已經想通的樣子。

語氣與句法依 [common-voice.md](../../.agents/skills/rui-xuan-book-v2/references/common-voice.md)；人稱按內容選擇，「我」可保留真實自問，「你／我們」可讓讀者代入。相關心得與真實材料依 [source-grounding.md](../../.agents/skills/rui-xuan-book-v2/references/source-grounding.md) 核對，不把討論中由 AI 提出的假設直接寫成作者的經驗或確定立場。

有稿件回饋時，按問題試讀、判讀或修訂，依需要使用 ai-reader、[ai-editor](../../.agents/skills/ai-editor/SKILL.md)；不固定每篇都跑完整角色流程。作者提出具體修稿需求時，回到當前正文與 diff 處理。

## 6. 質感怎麼判斷

先看問題與理解，再看句子是否漂亮：

- 讀得出這本書的具體觀點，以及作者為什麼在意它。
- 討論與文章有新的理解，沒有只換比喻、換例子重述同一個結論。
- 延伸概念有作用，也保留因果、條件與反例，沒有只留下口號。
- 能分辨書中說法、作者的想法與 AI 的推測，引用與經歷有來源。
- 文字能辨認作者的觀察與取捨，也容得下尖銳、溫度、不確定與改變。

這些是閱讀判斷，不是配額。不因符合人設、放入生命素材、引用另一本書或使用短行，就宣稱已寫出作者的思考。以實際稿件與作者的具體回應修正。

## 7. 使用與維護

現行陪讀與寫作 skills、人物參考、生命素材與心得目錄都已存在。這份計畫負責串起「一本書 → 討論 → 觀念延伸 → 形成自己的理解 → 讀書心得」；下一次可直接從一本書或一段感想開始。

人物資料已完成本輪整理，仍有近況與來源差異待補，詳見人物檔；它們按相關問題處理，不是所有讀書心得都要先排除的障礙。心得草稿保存於 `book-reader/讀書心得/`；需要發布時，另依 repo 規則更新 [網站書籍內容](../../site/src/content/books/)。

若討論要交給另一個 agent 接續，按 [vibe-handoff](../../../.agents/skills/vibe-handoff/SKILL.md) 保存當次書籍、正在追的問題、已形成的理解、已讀來源、作者的取捨與下一個未解問題。交接服務這一本書的討論，不把本計畫改成固定的人設待辦或 A2A 任務文件。

本輪完成的是計畫用途與流程的修正，未執行新的書籍討論或心得試寫；實際效果在後續單書討論與稿件中確認。
