# Design

## Decisions

- **稿件來源**：產生器直接讀 `book-reader/book/`，使用 Astro 現有 Markdown 處理器渲染，避免維護第二份書稿
- **閱讀順序**：部稿依 `部引言`、`練習`、`部小結` 拆成兩個閱讀區段，安插在該部三章前後；來源檔保持原樣
- **註解定位**：每個可註解區塊保存來源檔、原稿行號範圍、區段定位 id 與引用原文，讓後續修改用多重訊號核對
- **狀態擁有者**：閱讀頁的單一客戶端腳本擁有註解、面板與閱讀位置；持久化只同步至 `localStorage`
- **資料交換**：JSON 用於完整備份與匯回；Markdown 用於直接閱讀修改建議。另提供一鍵複製的 ChatGPT 交接稿，要求保留定位欄位。匯入時驗證格式與必要欄位，再依註解 id 合併
- **離線範圍**：產生器輸出單一 HTML，使用系統字型、內嵌書稿、樣式與腳本；預設只綁本機，明確使用手機模式時才開放同一區域網路存取，執行時不呼叫外部服務
- **公開範圍**：使用者明確指定放到 GitHub Pages；正式建置產物位於 `/manuscript/`，本機與正式生成物本身都由 Git 忽略，只提交產生器與模板
- **離線快取**：以手稿 HTML 內容雜湊建立 service worker cache 版本；首次成功載入後，導覽請求失敗時回傳快取頁面

## UX States

- 無註解時顯示用途與新增方式
- 儲存、更新、刪除、匯出與匯入都有可見狀態訊息
- 匯入格式錯誤時保留現有註解並顯示可修復訊息
- 桌面版使用固定註解欄；窄螢幕使用可關閉的底部面板
- 每個段落提供鍵盤可聚焦的註解按鈕，選取文字後也可建立註解

## Export Contract

JSON 根物件包含 `format: "rui-xuan-manuscript-notes"`、`version: 1`、匯出時間與 `notes`。每筆註解包含 id、來源檔、閱讀區段、區塊 id、章節標題、引用文字、建議內容及建立／更新時間。
