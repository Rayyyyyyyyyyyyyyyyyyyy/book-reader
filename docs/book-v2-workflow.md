# 新書寫作流程（book-v2）

> 2026-09-18 建立。記錄《把自己的部分做完》新版正文的逐章產出流程、分工與檢查。故事與章節功能依 `docs/chapter.md`，聲音依 `.agents/skills/rui-xuan-book-v2/SKILL.md`。

## 檔案位置

| 檔案 | 用途 |
|---|---|
| `book-reader/book-v2/NN-章名.md` | 正文，一章一檔 |
| `book-reader/book-v2/_continuity.md` | 跨章事實與每章「資訊邊界」（沒說出口的事、誰不知道什麼） |
| `book-reader/book-v2/_feedback/NN-scenes.md` | 本章場景表：地點與配備、時間天氣、人物、物件歸屬、各自知道的事 |
| `book-reader/book-v2/_feedback/NN-reader.md` | 讀者回饋 |
| `book-reader/book-v2/_feedback/NN-editor.md` | 編輯判讀與修訂清單，末尾附潤飾紀錄 |
| `book-reader/book-v2/_feedback/NN-audit.md` | 一致性稽核帳本與修正清單 |
| `docs/book-v2-pipeline.sh` | 執行流程的腳本 |

執行 log 預設寫在 `~/.cache/book-v2-logs/`，不進 repo。

## 執行方式

- 一次一章，依故事順序；整章完成、檢查後 commit 一次
- 每一步都開新的 `codex exec` session，不共用上下文
- 模型 `gpt-5.6-sol`，reasoning effort high（使用者也接受 `gpt-6-astra` high；同一本書盡量維持同一模型）

```bash
docs/book-v2-pipeline.sh full   07 "住在一起以後" "第七章｜住在一起以後" "8,000–9,000"
docs/book-v2-pipeline.sh expand 01 "十一點的電話" "第一章｜十一點的電話" "6,000–7,000"
docs/book-v2-pipeline.sh audit  06 "這一次，我們真的在一起了" "第六章｜這一次，我們真的在一起了"
```

- `full`：新章，寫作→讀者→編輯→潤飾→稽核
- `expand`：既有章擴寫到目標字數，第一步改為以現稿為底展開場景，保留作者手改過的句子，其餘四步相同
- `audit`：只跑一致性稽核

Codex 的即時過程直接輸出在執行腳本的 terminal（由 Claude 在背景執行時，可在 Claude Code 的背景任務輸出中查看）；同時存成 `~/.cache/book-v2-logs/NN-步驟.log`，最後回報在 `NN-步驟.last.md`。

## 每章五步

| 步驟 | Skill | 做什麼 | 產出 |
|---|---|---|---|
| 1 寫作 | rui-xuan-book-v2 | 先寫場景表，再照表寫正文；追加連續性與資訊邊界；量字數 | 正文、scenes、continuity |
| 2 讀者 | ai-reader | 以第一次讀的人回應：閱讀反應、畫面感、人物、時間與前後是否合理、hook、觀念 | reader |
| 3 編輯 | ai-editor | 合併讀者意見並分級；分開「刪同義反覆」與「補場景」；列修訂清單與字數目標 | editor |
| 4 潤飾 | rui-xuan-book-v2 | 執行清單；新增場景前先查場景表與全章相關段落；量字數；寫潤飾紀錄 | 正文、editor 末尾 |
| 5 稽核 | （無） | 逐段建帳本，只抓事實矛盾並最小修正，補資訊邊界 | 正文、audit、continuity |

稽核碰到作者手改或確認過的句子不直接改，列入 `NN-audit.md` 的「留給作者決定」並附建議改法，供作者人工校閱時參考。

之後由 Claude 整章讀過，照下方清單核對，再 commit；回報時列出「留給作者決定」的項目。

## 篇幅

全書目標 10–12 萬字，各章範圍見 `docs/chapter.md`「篇幅、引用與驗收」。字數計法：不含標題行與空白，含標點。長度來自場景完整展開，不靠形容、同義反覆或回看說理。

## 一致性清單

稽核步驟與 commit 前的人工核對都用這份：

- **設定推導**：細節從已建立的設定推出，不從類型預設補上
- **物件歸屬**：照片是誰的手機拍的、東西是誰帶的、誰付的錢
- **時間與狀態延續**：時段、天氣、濕掉或受傷的東西在後面合理延續
- **資訊邊界**：人物只知道自己實際得知的事；他沒說出口的念頭、願望、計畫，她不知道
- **對白呼應**：笑點或回扣讀得出在接哪一句
- **動作可演出**：動作順序在空間裡做得到
- **年代器物**：舊式手機、電腦等器物的操作合乎當年實際
- **擴寫殘留**：舊摘要已被新場景演出時要刪去，不讓同一件事發生兩次

## 使用者修稿偏好

從作者手改序章到第六章（及擴寫後的序章）歸納，寫作與潤飾都要遵守（第 1、2、4 條也已寫入 `rui-xuan-book-v2` skill 的「語言」一節，適用於所有書稿）：

1. **不用真實店名**：以「小茶坊」這類通稱代替可辨識的店家
2. **不把潛台詞說白**：對白不替人物解釋自己為什麼這樣說；能用動作接上的，就不再補一輪問答
3. **對白口語、直接**：說人真的會說的話，例如「我只是想見妳」「我現在沒有時間」，不用「我是想幫妳」這類較抽象的說法
4. **一個時刻只留一個細節**：同一段不堆多個物件或感官描寫，選最有作用的那一個
5. **用字求準**：時態（「也會去」與「也有去」）、場所（百貨而非商場）、比喻語氣（「好像」）、說法（「感情狀態」）都要貼合當下
6. **對白邏輯**：說話者、代名詞與呼應要接得上前一句或剛發生的動作
7. **動作要合乎實際安排**：例如軍人的休假是刻意安排的，不是把工作排開；需要定時的是餵罐頭，不是清貓砂
8. **物件要合乎實際使用**：例如按亮手機先看到的是鎖定畫面，不會直接停在備忘錄
9. **用詞貼合事實與行話**：職位被裁撤是「位子不復存在」，不是「椅子不屬於我」；事故處理說「止損」而非「止血」
10. **不為具體而編造過細的數字或規格**：例如「照著筆記上的三個詞」改為「準備好的說辭」；細節要有作用，不是越精確越好
11. **動詞平實**：「反過來放」而非「反扣」，不用偏文學的替代詞
12. **說同一件事的相鄰短段落併成一句**
13. **改編說明不放進正文章節**：交代改編性質留給書前說明，章節正文直接進入故事

## Commit 規則

- 每章 commit 一次，只加入該章正文、該章回饋檔（scenes／reader／editor／audit）與 `_continuity.md`
- 使用者手動修改的其他章節不處理、不 commit
- 回饋檔與 `_continuity.md` 照常隨流程更新

## 為什麼加入場景表與稽核

第六章完成後，使用者讀出八處前後矛盾：豪華露營後段變成自己煮鍋、在帳篷外刷牙；她知道他沒說出口的流星願望；合照明明是她的手機拍的，卻要他傳原檔；外套隔天還在滴水；對白笑點接不上；坐在駕駛座替副駕開門。追查結果：

1. 其中六處出自寫作初稿。一次寫近萬字時，細節是依類型預設當場生成的；提高字數與細節要求後，錯誤機會跟著增加，卻沒有對應的核對
2. 兩處出自潤飾新寫的場景，只接好相鄰段落，沒有回查全章相關物件
3. 讀者步驟以第一次讀的人回應，看不見資訊邊界越界；編輯步驟的注意力在結構，沒有逐行核對事實
4. `_continuity.md` 只記發生的事，沒記誰不知道什麼
5. commit 前的人工檢查只核對章卡事件是否出現，沒有整章讀過

因此加入寫作前的場景表、潤飾新增場景前的回查、獨立的稽核步驟、連續性的資訊邊界，以及 commit 前整章閱讀。
