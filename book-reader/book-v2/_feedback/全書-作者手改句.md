# 全書作者手改句清單

> 由 `docs/book-v2-pipeline.sh` 的同一套邏輯產生：取 commit 訊息含 `hand edit` 的提交中、該章檔案的**新增行**，只保留目前仍在正文裡的句子。

## 這份清單為什麼要進版控

原本只存在 `~/.cache/book-v2-logs/NN-author-lines.md`，每次跑流水線重新產生、不進 repo。後果：新的 session 看不到、建對照庫的 codex 拿不到，而 `NN-audit.md` 只寫「作者手改句清單共十句，全部原樣保留」這種**數量**，不寫內容。全流程最有價值的材料（作者親筆句）反而是唯一不落盤的東西。

## 可信度警告：五章被整章凍結

抽取邏輯取的是「帶 `hand edit` 的 commit 裡的新增行」。若某章**第一次入庫**時 commit 訊息就含 `hand edit`，那一次 diff 的每一行都是新增行，整章都會被當成作者手改句。`docs/book-v2-handoff.md` 警告過這個坑（第七章），但沒有人回頭檢查它已經發生在別章。
