## 一、這個 repo 有兩個產品

1. **`site/`**：Astro 5 靜態網站「百冊 · One Hundred」，部署到 GitHub Pages。書籍資料與已發布的讀書心得在 `site/src/content/books/`，一本書一個 Markdown 檔。建置期會由腳本產生封面與書稿閱讀器，那三個目錄是 gitignored，不要手動編輯。
2. **書稿**：`book-reader/` 底下的書稿與心得，加上 `docs/book-v2-pipeline.sh` 這條以 `codex exec` 驅動的逐章寫作流水線。網站與書稿只透過建置腳本相接。

書稿有兩份，不互相覆蓋：

- `book-reader/book/`：v1 完稿，也是網站 `/manuscript` 閱讀器實際發布的內容。
- `book-reader/book-v2/`：進行中的新版《把自己的部分做完》，一章一檔，另有 `_continuity.md`（跨章事實與資訊邊界）與 `_feedback/`（每章的回饋檔）。

其他：`book-reader/讀書心得/`（心得稿，檔名即書名）、`book-reader/is-me/`（私人生命素材，不發布）、`docs/my-story/`（作者的原始敘述，改編的素材來源）、`docs/chapter/`（book-v2 的章節腳本）、`openspec/`（規格與變更紀錄）。

## 二、這本書是什麼

《把自己的部分做完》是經作者授權的改編敘事書稿，第一人稱，寫他和同一個人從國中認識到分開的十幾年。序章、第一到十二章、結語。

**定位**：故事為主、每章都有可帶走觀念的成長書，但觀念完全由故事承接。三個曾經承載觀念的機制都已取消：

- 2026-09-18 取消四篇部稿
- 2026-09-20 取消章末 `## 回頭看`，第一到四章已寫好的四節全部刪除
- 2026-09-20／21 刪掉正文裡的旁白主題句與事後評語（序章、第二、三、五、六章各一到兩句）

**代價是辨識度**：讀者讀完會難過，但不一定講得出帶走了什麼。**補救方案是書末寫一篇後記**，由現在的我用一頁交代書名的意思——全書唯一一次旁白現身，放在故事之後。這篇還沒動筆。書名維持《把自己的部分做完》，由後記兌現。

## 六、流程

```bash
docs/book-v2-pipeline.sh full   NN "檔名標題" "章卡名稱" "<目標字數>"   # 寫作→讀者→編輯→潤飾→稽核
docs/book-v2-pipeline.sh expand NN ...                                  # 以現稿為底展開場景
docs/book-v2-pipeline.sh review NN ...                                  # 作者改過結構後重跑後四步，不重寫
docs/book-v2-pipeline.sh audit  NN "檔名標題" "章卡名稱"                 # 只跑一致性稽核
```

- 每一步都是全新的 `codex exec` session（`gpt-5.6-sol`，high），每步限時 30 分鐘。log 在 `~/.cache/book-v2-logs/`。
- Codex 額度用完時，可改用 Claude subagent 跑同樣的步驟（今天第七章的擴寫與讀者就是這樣跑的），prompt 要自己帶上 skill 與偏好的路徑。
- **`expand` 會整章展開**。只想改某一段時不要用它，改成自己寫 prompt 指定範圍。
- 作者手改句：腳本從含 `hand edit` 的 commit 抽出；還沒 commit 的用 `EXTRA_AUTHOR` 指一個每行一句的檔案帶進去。第七章的清單在 `~/.cache/book-v2-logs/07-extra-author.txt`。

## 七、今天學到、已寫進規則的事

**問題**：「寫完一幕，再用一句說明它的意思」反覆出現，刪掉幾句就長出新的幾句。原因是那是模型的預設收尾方式，而點名刪除只會產生替代品。

**處理**：
1. `.agents/skills/rui-xuan-book-v2/SKILL.md` 新增「命名與金句」一節，核心是代價測試——**這句話說出來，說話的人損失了什麼**；零代價的句子是死的。底下有「收束檢查」：每一場寫完後看最後一句，**把它刪掉場景若仍成立，就刪掉**。最後自檢也加了同一項。
2. `docs/book-v2-pipeline.sh` 的稽核機械檢查從 a–f 變成 a–g，第 g 項要求抓出每一場與每一段的最後一句，標記是畫面、動作、對白還是結論，結論全部列給作者。潤飾那一步也加了同一個檢查。

這套規則來自 `docs/日劇金句脈絡-冬のなんかさ春のなんかね.md` 的研究，那份文件已回寫，註明哪些結論進了 skill。

## 八、規則重點

- **書稿等作者校閱同意才 commit**；提交時逐一指定檔案，**不要用 `git add -A`**（今天犯過一次，把未校閱的第七到十三章掃進去，已 reset 重來）。
- 作者手改句原樣保留；與事實衝突時列進「留給作者決定」，不直接改。
- 修稿偏好 33 條在 `docs/book-v2-workflow.md`，寫作與潤飾都適用。重點：不用真實店名、不把潛台詞說白、一個時刻一個細節、用字求準、不放事後評價與主題句、熟悉的感受不再拆解、寧可刪贅詞不為字數補句、例子少而完整。
- 正文不寫年份數字；句尾原則上不留標點；不使用破折號；貓叫黑糖，代名詞用「牠」。
- 流程腳本、章節腳本與文件的修改照常直接 commit。
