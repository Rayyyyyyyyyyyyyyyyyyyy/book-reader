# Book V2 正文直接修改

這是 `rui-xuan-book-v2` 的**直接修改正文分支**。直接修改 `book-reader/book-v2/*.md` 正文時，不論整章或只改幾句，都先執行本流程；依清單或回饋補寫、套用作者裁定、潤飾既有章節也一樣。

由 `docs/book-v2-pipeline.sh` 啟動的 `codex exec` 步驟，其 prompt 已直接送入必讀材料，不重跑本門檻。只讀、診斷、統計或回報不觸發。

## 先確定章號與改動範圍

先確認要動的是哪一章、哪些段落、改動要解決什麼。範圍不清楚時可以先讀正文定位，但不得先試寫、先套 patch，再回頭補引文。

## 取材順序

以下材料要在**同一輪對話內實際開檔**，不得拿 session 稍早的摘要、自己先前寫過的文件或印象代替。只擷取直接管到本次改動的內容，但不能只挑支持預定修法的句子；限制、反例與「該留不動」也要讀。

1. `book-reader/book-v2/_feedback/全書-作者手改句.md` 的該章段落：作者親筆句本身，是最直接的正例，優先於條文。先讀檔案開頭的可信度警告，再判斷該章清單能不能當樣本。
2. `docs/chapter/NN-*.md` 的該章章卡：確認本章要成立什麼、不做什麼、篇幅與停點。
3. `book-reader/book-v2/_feedback/NN-audit.md` 的「作者手改保護」，以及 `NN-editor.md` 末尾的潤飾紀錄與 Claude／作者校閱紀錄：確認已認證的保護範圍、上輪實際改動與作者退回內容。
4. `docs/book-v2-workflow.md`「使用者修稿偏好」中直接管到本次改動的條目：先用「主題索引」找條號，再逐條讀原文與例子。不要抄四十條，也不要憑記憶轉述。
5. `book-reader/book-v2/_feedback/全書-人物弧線.md`：讀 A／B／C 分層、本章成熟度定位，以及本章「不能提早出現」。
6. `book-reader/book-v2/_feedback/全書-手改對照.md` 的按章索引、相關 before／after 與親筆句樣本：先看樣本怎麼寫，再用條文理解為什麼刪。
7. 與本次段落或問題相關的 `book-reader/book-v2/_feedback/全書-*.md` 掃描：連同其中的「該留不動」、前提更正、作者裁定與未套用狀態一起讀。
8. 本 skill 的 [`adapted-narrative.md`](adapted-narrative.md) 分流：用來決定聲音、人物基準與敘事寫法，不取代上述章級材料。

若某章缺少流程檔，先讀 `_feedback/README.md` 確認是刻意空缺還是尚未產出；不要自行假設內容。

### 數量不等於內容

`NN-audit.md` 常寫「作者手改句清單共十句，全部原樣保留」。這只是流程已核對的證明，不是可供模仿或保護的實際材料。看到數量摘要，仍須回到 `全書-作者手改句.md` 讀該章真正的句子；不能因 audit 說已照顧到就跳過。

### 兩套「第 N 條」不能混用

- `docs/book-v2-workflow.md` 的「第 N 條」是**使用者修稿偏好**。
- `_feedback/全書-人物覆蓋率.md`、`全書-人物補寫清單.md`、`全書-人物弧線.md` 的「第 N 條」是 `book-reader/is-me/Rui-Xuan.md` 的**十二面向人物分析**。

引用時一律寫清楚是哪一套，不用裸編號。

### 五章的作者手改句清單受污染

第 05、08、12、13、14 章曾在章節第一次入庫時使用含 `hand edit` 的 commit 訊息，抽取器因此把整章新增行都當成作者手改句。這五章在 `全書-作者手改句.md` 的段落等於整章正文，**不能當作者親筆樣本，也不能把整章視為不得改動**。

要讓後續 `review`／`audit` 保護這些章真正的作者手改句，先把已確認且仍在正文裡的句子逐行放進一個額外檔案，再用 `EXTRA_AUTHOR` 指向它，例如：

```bash
EXTRA_AUTHOR=~/.cache/book-v2-logs/05-extra-author.txt docs/book-v2-pipeline.sh review 05 ...
```

新章第一次進版控時，commit 主旨不要寫 `hand edit`；用 `EXTRA_AUTHOR` 保護指定句子，避免再次把整章凍結。

## 引文門檻

動筆前，先在對話裡輸出一份引文清單。每條都必須：

- 逐字照抄，附檔名與行號。
- 來自這一輪實際開過的原檔，不引用自己先前的摘要。
- 說明它直接管到哪一處預定改動。
- 同時納入正例、限制、「不能提早出現」與「該留不動」；沒有相關內容時，明說查過哪個檔案與區段、結果為何。

**貼不出來就是沒讀，沒讀不動筆。** 摘要可以憑印象生成，引文不行；引文缺席時，作者一眼就能看出門檻沒有執行。

這道門檻防的是三種已發生的失效：

1. **自己的摘要取代原檔**：轉述有損，卻因為離當前 context 較近而被當成來源。
2. **編輯過某份文件，誤以為讀過內容**：知道流程欄位或曾改過說明，不等於看過任何一則實例。
3. **讀過的會隨 session 變舊，自信不會**：早期讀到的內容可能已被摘要替換，使用它時的把握度卻沒有同步下降。

## 動筆

引文清單完成後，先為每一處預定改動列出：

- **依據**：對應哪一條逐字引文。
- **護欄**：它不違反哪一條引文，尤其是作者親筆句、章卡停點、人物弧線與「該留不動」。

再依這份對照修改正文。改動擴大到原先未涵蓋的段落時，先補讀材料與引文，不沿用既有清單推測。

若來源彼此衝突，或作者裁定與既有條文、章卡、人物弧線不相容，立即停手，把衝突的逐字引文、位置與各自會造成的結果列給作者；不得自行判定哪份來源失效，也不得用閱讀體驗、規則優先級或「應該是作者想要的」代替裁決。

## 交件與作者校閱完成後

交作者校閱時，回報實際改了哪些位置，並逐處附上「依據／護欄」對照；沒有執行的建議與仍待作者裁決的衝突分開列出。不要把完成直接修改誤報成作者已核准定稿。

只有作者明確說「第 N 章改好了」或同等意思時，才依 `docs/book-v2-workflow.md`「作者校閱完成後」執行完整七步，不得只 commit：

1. 核對定稿。
2. 同步事實。
3. 從本輪手改迭代修稿偏好。
4. 重新產生並檢查 `_feedback/全書-作者手改句.md`。
5. 更新 `docs/book-v2-handoff.md` 的字數、狀態與承接事項。
6. 精準提交並核對 staged diff；不用 `git add -A`，章節 commit 主旨依規則包含 `hand edit`。
7. 回報 commit、定稿字數、新增或補充的修稿原則，以及未解決項目。

若作者只核准一句或幾處，僅套用該局部裁定，不把它視為整章校閱完成。
