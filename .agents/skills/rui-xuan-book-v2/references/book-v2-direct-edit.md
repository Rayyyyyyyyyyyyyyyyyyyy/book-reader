# Book V2 正文直接修改

這是 `rui-xuan-book-v2` 的**直接修改正文分支**。直接修改 `book-reader/book-v2/*.md` 正文時，不論整章或只改幾句，都先執行本流程；依清單或回饋補寫、套用作者裁定、潤飾既有章節也一樣。

由 `docs/book-v2-pipeline.sh` 啟動的 `codex exec` 步驟，依其 prompt 取材，不重做同一套準備。只讀、診斷、統計或回報不觸發。

## 先確定章號與改動範圍

先讀當前正文與相關 diff，確認這次要解決的閱讀問題；局部修句讀前後段，結構或人物問題讀整章與必要的相鄰章。作者已請求修稿時，在可確認的範圍內直接提出並實作有力的修改，不另把每個句子送回作者批准。若問題尚未定位，可先讀稿、試擬候選，再選最能改善閱讀體驗的寫法。

## 按問題取材

本輪實際開啟當前正文與相關 diff；摘要只能用來定位，不能代替原稿。其他材料依問題選取，不為小幅修句固定讀完一整串檔案：

- **章節功能、場次、停點或篇幅**：讀本章 `docs/chapter-v2/NN-*.md`；有跨章影響時再讀相鄰章卡與 `_continuity.md`。
- **人物聲音、動機或成熟度**：讀相關的 `_feedback/全書-人物弧線.md`、章級回饋與可核實的手改樣本；只讀能管到本次問題的區段。
- **作者曾改過的句子或被退回的修法**：對照現稿、diff、`_feedback/全書-手改對照.md` 與相關回饋，確認原句與取捨。`全書-作者手改句.md` 是 Git 候選快照；第 05、08、12、13、14 章首次入庫曾誤標整章，不能據此認定都是作者親筆或不可改。
- **具體語氣或風格問題**：查 `docs/book-v2-workflow.md` 中相關修稿偏好及原句例子，並依 [`adapted-narrative.md`](adapted-narrative.md) 判斷敘事效果；不把四十條當成逐條驗收表。

取材時也看相關的反例、前提更正與「該留不動」；它們是理解舊取捨的證據，不是自動否決新修法的命令。資料缺席時按現稿與已知設定判斷，不為補齊流程檔而停工。引用「第 N 條」時寫明是修稿偏好還是人物分析，避免兩套編號混用。

## 核對與動筆

讀過相關原稿後，先找造成閱讀障礙的真正原因，再修改必要的句子、段落或場景；可刪、重排、補寫，也可保留已有效的部分。修改擴及新場次、時間、人物知情範圍或跨章事實時，補讀對應材料並同步相關紀錄。不要讓「只准小修」使問題留在原處。

不設動筆前的逐字引文清單或逐處「依據／核對」表。需要向作者說明關鍵判斷時，引用本輪讀過的原句並標出位置；交件時概述問題、實際修法及有意識保留的取捨。動到**可確認的作者親筆句**，另保留原句、改後句、來源與理由，供作者校閱。

作者本輪明確裁定可覆蓋舊章卡、回饋與保護語句。遇到衝突，依最新裁定修稿並記下實質取捨；只有事實歸屬、授權範圍或會改變故事核心的選擇仍不明時，才請作者決定。舊文件的「不動」不能代替本輪判斷。

## 交件與作者人工潤稿

對話與親密互動的局部修改，依 [dialogue-and-intimacy.md](dialogue-and-intimacy.md) 連讀受影響的整輪互動並對照改前稿；修掉缺口後再交件，不以已增加台詞、動作或笑聲認定效果成立。

交作者校閱時，回報主要改動及其對整段閱讀的作用；動到可確認的作者手改句時，另記原句、改後句、來源與理由。沒有執行的建議與仍待作者裁決的衝突分開列出。不要把完成直接修改誤報成作者已核准定稿。

作者仍在手改時，讀現稿與 diff 以理解其用意；被指出不順、怪異或因果不成立時，回到上下文協助修稿。先暫記改動來源與取捨，不把候選句升格為正式偏好。

作者說「第 N 章看完了／改完了／改好了」時，通讀整章與本輪 diff，客觀回報哪些改動有效、哪些有疑慮，給出具體建議。只有存在會實質改變人物、事件或章節效果、需要作者選擇的分歧時，才列不同方向與取捨；不為每個句子湊兩個選項。單說「看完了」仍是評讀關口，不等於授權直改、核准定稿或 commit；若作者同時請求修稿，則可按本流程直接修改，交作者校閱。只有作者明確說「這章 OK／可以定稿／同意提交」時，才依 `docs/book-v2-workflow.md`「作者確認這章 OK 後的七步」執行，不得只 commit：

1. 核對定稿。
2. 同步事實。
3. 從本輪手改迭代修稿偏好。
4. 核對手改來源並更新 `_feedback/全書-手改對照.md` 與本輪手改紀錄；`全書-作者手改句.md` 僅作 Git 候選快照，不得把整章新增行誤認成作者親筆。
5. 更新 `docs/book-v2-handoff.md` 的字數、狀態與承接事項。
6. 精準提交並核對 staged diff；不用 `git add -A`，只有確實提交作者親筆修稿時主旨才包含 `hand edit`。
7. 回報 commit、定稿字數、新增或補充的修稿原則，以及未解決項目。

若作者只核准一句或幾處，僅套用該局部裁定，不把它視為整章定稿；若說「先不要提交」，不執行提交。
