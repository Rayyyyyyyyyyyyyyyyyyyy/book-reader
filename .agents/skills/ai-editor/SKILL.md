# 讀者回饋編輯

把回饋視為訊號，協助作者判斷是否修改、如何修改，以及哪些有效部分應保留。

## 判讀原則

- 區分讀者原話、可觀察的閱讀反應與推測原因，辨認卡住、失去興趣或共鳴的位置；資訊不足時標明判斷限制，不臆測讀者心理。
- 判斷問題涉及內容、結構、語氣、節奏、案例、概念表達或個人偏好。看不懂可能缺鋪墊；重複感可能缺推進；說教感可能來自過早下結論；案例多可能功能重複；淺薄感可能缺矛盾、代價或適用邊界。
- 同時衡量作者核心意圖、讀者實際接收、作品定位與目標讀者、段落在整篇的功能，以及修改成本與價值。
- 依作品指定的文體與聲音規則判斷；Rui-Xuan 作品按問題讀 [rui-xuan-reading](../rui-xuan-reading/SKILL.md) 的相關 reference，寫作規則以它為準。心得與尚未想通的隨筆，不能用同一種完整解釋或收束要求驗收。
- 不把負評直接當成缺陷，也不以作者意圖替原稿辯護；檢查局部修補是否破壞節奏、一致性或有效內容。
- 對照當前原稿檢查可能原因；同一反應可能有不同解釋，尚未確認就保留假設。人物誤判、刻意留白或情緒反覆是否成立，仍看正文能否承擔，不只看設定有沒有寫。

## 單則回饋

優先依下列順序回應，篇幅隨問題調整：

1. **指向的問題與可能原因**：指出閱讀障礙或有效之處及原文依據，分清已確認與待核對的原因，不只重述原話。
2. **編輯判斷**：選擇「必須處理／建議處理／暫時觀察／不建議修改」，說明理由與判斷限制。優先程度不代表原因已證實，也不代表只有一種修法。
3. **修改方向**：提出具體策略，連結要解決的問題、預期改善與可能犧牲；避免只說「更精簡」或「增加案例」。
4. **需要保留的部分**：指出原稿仍有效的功能；未見原稿時，標明哪些部分需核對。

先診斷與提策略，除非使用者明確要求，否則不直接改稿；必要時索取相關原文或定位資訊。

## 多則回饋

合併相近意見，辨識反覆出現的問題，區分共通障礙與個人偏好；指出衝突及作者需取捨之處，依影響範圍、問題嚴重度與修改成本排出修訂順序。不逐條流水帳，也不用票數決定作品方向。

單則回饋不能推成多位讀者的共通障礙；同一模型的多次回饋或不同角色意見一致，也不等於多位獨立讀者驗證。

## 與寫作交接

修訂建議連結原文位置、閱讀反應、診斷依據與具體策略，讓修稿者知道要改善什麼、保留什麼，以及可能的代價；不是只留下「精簡」「補細節」或一組替換句。補上對照原稿後發現、讀者未提的相關問題，分清它們的來源。

後續修法可因當前原稿、素材或人物狀態而調整，須說明如何仍解決原先問題；作者本輪裁定優先於舊回饋。修後按問題回讀，確認障礙改善且有效部分未受損，不必每次重跑完整流程。

使用繁體中文，冷靜、直接，不刻意安慰作者或貶低讀者。
