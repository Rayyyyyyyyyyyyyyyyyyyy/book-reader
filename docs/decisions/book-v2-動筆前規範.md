# 為什麼 book-v2 直接修改需要動筆門檻

> 狀態：機制決策紀錄，不是另一份操作手冊。現行操作以 `.agents/skills/rui-xuan-book-v2/references/book-v2-direct-edit.md` 為準。

> 現行操作流程已併入 `.agents/skills/rui-xuan-book-v2/references/book-v2-direct-edit.md`。本檔只保留這道門檻的由來與失效分析，不再承擔操作指示。

## 2026-09-23 的失敗

Claude 依人物補寫清單修改了十三處正文，作者校閱後刪掉九處；其中八處的共同點，是每句對白後面都掛一個身體小動作。

事後檢討發現，問題不是單純的品味差異，而是**憑印象動手**：修改前沒有讀該章章卡、沒有重讀直接相關的修稿偏好，也沒有讀該章的作者手改保護與親筆句。模型知道有這些規則，卻沒有取得這次改動真正需要的材料。

## 三種已辨認的失效機制

1. **自己的摘要取代原檔。** 早先讀過、並向作者轉述過的內容，會在後續 turn 被當成來源使用。轉述是有損的，但它在 context 裡更近、更順手，最後變成引用自己而不是引用來源。
2. **編輯過不等於讀過。** 寫過某份文件的某個欄位，會產生「我熟這個」的錯覺；知道「作者手改保護」怎麼運作，不代表看過該章任何一則親筆句。
3. **讀過的會變舊，自信不會。** 早期 turn 讀到的內容可能已被 session 摘要替換，使用它時的把握度卻沒有同步下降。

## 為什麼再寫一條規則沒有用

當時 `CLAUDE.md` 已以粗體要求先讀 `AGENTS.md`，這句話從 session 開始就在 context 裡，仍然被跳過。把同一要求再複製到更多被動文件，只會增加一個等待 agent 主動想起來的入口，不會改變失效機制。

流水線之所以較可靠，是因為必讀材料跟著任務進入 prompt，而且讀取結果會被下一個輸出綁住。直接修改正文也需要同樣的結構：由**任務情境觸發 skill**，先在對話交出逐字引文，才進入修改。

引文門檻的理由很簡單：摘要可以憑印象生成，引文不行；引文在對話裡缺席時，作者一眼就看得出來。真正有效的不是「記得先讀」這句提醒，而是把已讀證據變成動筆前可見、不可省略的產物。

這也是操作流程必須放進 `.agents/skills/rui-xuan-book-v2/` 的原因：被動文件等人來讀，skill 跟著任務到達。它現在是同一 skill 的正文直改 reference，避免聲音規則與動筆門檻由兩個重疊 skill 分別觸發。
