## 執行方式

- 一次一章，依故事順序；整章完成、檢查後先交作者校閱，明確核准後才 commit
- 每一步都開新的 `codex exec` session，不共用上下文
- 模型 `gpt-5.6-sol`，reasoning effort high（使用者也接受 `gpt-6-astra` high；同一本書盡量維持同一模型）

```bash
docs/book-v2-pipeline.sh full   08 "住在一起以後" "第八章｜住在一起以後" "8,000–9,000"
docs/book-v2-pipeline.sh expand 01 "十一點的電話" "第一章｜十一點的電話" "6,000–7,000"
docs/book-v2-pipeline.sh audit  07 "這一次，我們真的在一起了" "第七章｜這一次，我們真的在一起了"
```

- `full`：新章，寫作→讀者→編輯→潤飾→稽核
- `expand`：既有章擴寫到目標字數，第一步改為以現稿為底展開場景；若改動可確認的作者手改句，記下前後差異與理由，其餘四步相同
- `audit`：只跑一致性稽核

2026-09-20 作者決定取消章末 `## 回頭看`：第一至四章已寫好的四節全部刪除，第五章之後不再補寫，`reflect` 模式也從腳本移除。觀念只由故事與「現在的我」的短暫回看承接。

本書定位：故事為主、每章都有可帶走觀念的成長書，觀念由故事本身承接。部稿（2026-09-18）與章末回頭看（2026-09-20）都已取消；是否在書末附錄工具與練習，寫到書末時再討論。規則見 `docs/chapter-v2/00-總則.md`。

### 人設回歸檢查（潤飾步驟）

2026-09-23 加入，並在同日補成「改前基準＋改後回歸」兩段。人物分析直到全書寫完（`0b2a485`）才進入流水線，原先只進 `write` 與 `expand`；`reader` 不讀人物來源，`editor` 不拿人物分析驗收，`polish` 只執行刪重複與收句子，`audit` 只查事實。只在潤飾後問四題仍太晚：模型不知道改前哪些句子正承載人物，也無法證明自己沒有把它們修掉。

**第一段由 editor 建立人物基準。** 對照 `is-me/Rui-Xuan.md` 第 13 至 88 行、`_feedback/全書-人物弧線.md` 與 `_feedback/全書-手改對照.md`，記錄：

- 本章安全程度與允許出現的 A／B／C 時間層
- 現稿兩至四個已有辨識度、潤飾時要保留的人物訊號，逐字引用並標位置
- 他在本章除了處理問題還想從人身上得到什麼，以及如何要求或接受照顧
- 只有在章卡、人物分析與既有事件都有根據時，才列本章真正缺少的面向；十二面向不是每章配額

**第二段由 polish 做前後回歸。** 腳本在潤飾前保存正文快照；潤飾完成後逐項核對人物基準。原有訊號若消失，必須指出它與哪一個保留處完成相同的關係／人物功能，不能只寫「已保留人設」。再回答四題：

1. 把名字遮掉，還認得出是他嗎
2. 他這一場除了處理問題，還想從人身上得到什麼
3. 他只有照顧別人，還是也會要求與接受照顧
4. 本章的安全程度，與他表現出的檔位是否一致

缺少的面向若有既有素材與事件支持，透過選擇、對白、需求、拒絕或互動後果修回來；沒有根據，或會讓 C 層完成式自我理解提早出現，就寫進潤飾紀錄留給作者決定。**不要自行補一個小動作充數**——2026-09-23 那輪十三處被刪九處，八處就是這種補法。四題是回歸鏡頭，不是人物配額。

讀者步驟仍刻意保持盲讀，回答「沒看設定的人實際讀到了誰」；人物來源由 editor 與 polish 使用。audit 仍只查事實，不讓文風判斷混進一致性稽核。

## 篇幅

全書刪去章末回頭看後約 9 萬字，不為湊字數加場景；各章範圍見 `docs/chapter-v2/00-總則.md` 的「篇幅、引用與驗收」。字數計法：不含標題行與空白，含標點。長度來自場景完整展開，不靠形容、同義反覆或回看說理。

## 一致性清單

稽核步驟與 commit 前的人工核對都用這份：

- **設定推導**：細節從已建立的設定推出，不從類型預設補上
- **物件歸屬**：照片是誰的手機拍的、東西是誰帶的、誰付的錢
- **時間與狀態延續**：時段、天氣、濕掉或受傷的東西在後面合理延續
- **資訊邊界**：人物只知道自己實際得知的事；他沒說出口的念頭、願望、計畫，她不知道
- **對白呼應**：笑點或回扣讀得出在接哪一句
- **動作可演出**：動作順序在空間裡做得到
- **年代器物**：舊式手機、電腦等器物的操作合乎當年實際
- **擴寫殘留**：舊摘要已被新場景演出時要刪去，不讓同一件事發生兩次；同一問題或玩笑不在同一場對話重複
- **數量相符**：文中說的字數、次數、時長與實際內容一致

### 條文

持續從作者的手改與明確採納的修訂歸納，寫作與潤飾都要遵守。最初整理自序章到第六章，後續每章在作者確認「這章 OK」後，依下方「作者確認這章 OK 後的七步」正式迭代；不把尚在討論的候選句當成偏好（第 1、2、4 條也已寫入 `rui-xuan-book-v2` skill 的「語言」一節，適用於所有書稿）：

1. **不用真實店名**：以「小茶坊」這類通稱代替可辨識的店家
2. **不把潛台詞說白**：對白不替人物解說自己的動機或替讀者翻譯已成立的意思；動作已承擔這層解說時不補分析問答。當下的需要、邀請、關心、回應與玩笑可以直接說出；不以本條刪掉正常說話，敘事互動依本節的對話回讀入口處理
3. **對白口語、直接**：說人真的會說的話，例如「我只是想見妳」「我現在沒有時間」，不用「我是想幫妳」這類較抽象的說法。第十三章作者把被問「你拍這個幹嘛」後的回答「到了就拍了」改成「到此一遊」，用現成的口語成句代替解釋自己的動機
4. **一個時刻只留一個細節**：同一段不堆多個物件或感官描寫，選最有作用的那一個。第十二章進一步取消「每場至少一個身體細節」的配額；雨淋濕外套不必寫成衣料摩擦皮膚，書店不必靠舊車票、報紙與時鐘製造氣氛。細節須符合穿著與場景，也不因具體就必須留下。第八章後續手改將「手卻還放在滑鼠旁邊」收成「手卻還放在桌上」，保留停住的動作，省去無作用的物件定位
5. **用字求準**：時態（「也會去」與「也有去」）、場所（百貨而非商場）、比喻語氣（「好像」）、說法（「感情狀態」）、器物（電磁爐而非兩口爐）、動作結果（照片是糊掉不是晃掉）都要貼合當下。人稱也要符合誰在作決定：第五章作者將「我們就不要再像現在這樣見面」改成「我就不要再像現在這樣見面」，保留他對自己參與方式的選擇，不替雙方宣告共識。2026-09-25 同章再把指向不明的「從她家也看不到」改成「因為我不想遇到」，讓停車位置與他當時的顧慮直接相連；先查清句子指向誰、為何如此，再決定要不要加說明。2026-09-30 序章至第七章核准補充：先核對「第一次」、時段與回述的範圍是否符合前文。第一章已分享過生活，就不再宣告首次講自己的一天；第四章把「哪天不用上班」收準為「哪天有空」，接得上下班後見面，不另編換班原因
6. **對白邏輯**：說話者、代名詞與呼應要接得上前一句或剛發生的動作。第一章作者指出「那我要等多久」之後接「你現在不就在跟我聊天」既沒回答等待，也把連續提問誤稱為聊天；本輪採納先答「我哪知道，等她回啊」，再另起她自己的上課話題。序章同理：她已提出分手，就不能讓他仍以保留週五晚餐的安排當成這次談話的起手式；現稿改為請她先不要搬，她回答已談過很多次、不想再試。第九章男主角已說早上餵飼料、清貓砂本來就是他負責，女主角的反問就不能把早上當成他新提的要求；改為她承諾平日晚間照舊、週六早上換她，再問還要做什麼。先核對人物此刻在回應什麼，再判斷句子是否好看
7. **動作要合乎實際安排**：例如軍人的休假是刻意安排的，不是把工作排開；志願役的手機自己保管，只有出操、值勤、站哨時不能用；需要定時的是餵罐頭，不是清貓砂
8. **物件要合乎實際使用**：例如按亮手機先看到的是鎖定畫面，不會直接停在備忘錄

**2026-09-23 型二改成三個判斷角度**（全書親密對話掃描後重訂，見 `book-reader/book-v2/_feedback/全書-親密對話.md`）。原本的單一門檻「這一段之後，有沒有人知道了新的事，或失去了什麼」不再單獨使用，因為打情罵俏照定義就過不了它——型二明文要刪的正是「連著幾段確認同一個狀態或**同一份親密**」。改成依序問三個問題。**它們是看的角度，不是通關流程**；某一段明顯成立時不必跑完三題，也不要求每一段都答得出三個答案：

1. **先看事件是否推進**：有人得到新資訊、作出選擇、承擔代價、改變安排，或心理狀態發生變化
2. **再看關係是否推進**：兩人是否第一次建立、恢復或改變一種共同語言、身體默契、可接受的玩鬧邊界、主動靠近的方式、拒絕之後仍能相處的節奏，或修復後重新嘗試的安全感。**這些本身就算推進**，不必同時有新資訊或損失
3. **最後才查是否重複**：問法不是「這幾段都在證明他們親密嗎」，而是「它們完成的是不是同一個**關係功能**」。第一次敢碰、第一次會回碰、吵完後第一次敢再鬧，各自不同

- **只有他們測試**：這個玩笑或動作換到任意一對情侶仍成立，通常只是裝飾；它若依賴兩人共同經歷、對方習慣、舊物或剛才的失誤，就可能正在建立共同語言
- **下一次會不會不同測試**：這一拍之後，下一次同類互動是否多了一點允許、預期或風險。從不敢碰到敢搶、從只接收照顧到會回敬、從不敢玩到試著越過紙膠帶，親密本身已經往前走

**沉默要有承擔者。** 判準是：這個沉默是**他說不出來**，還是**作者懶得讓他說**。前者由場景承擔——寫出對方的等待、他的卡住，或他一開口就會把已經結束的事變回挽回；後者只是省略。常見成立的有：正在消化足以讓人失語的消息、真的沒有答案、忍住不說才是那場的重點、不等個人答覆的集體通知。**這不是窮盡清單**，新的情況照判準自己判。比較確定不成立的是別人剛幫完忙、道歉、邀請、問候或提供具體照顧之後，那裡的沉默通常只是沒寫。

**單音節要有下一拍接住。** 判準是：這個「嗯」之後，有沒有動作、下一句或對方的反應把回合完成。有就成立，沒有就是把人物關掉。封閉式的辦事問句本來就只需要「要／不要」；他在重大消息裡只說得出這麼多也成立，但要稀有，而且靠場景的重量支撐，不能流遍工作、朋友與服務往來。**同一章出現第三個沒有下一拍的單音節，就回頭看是不是把他寫成了愛理不理。**

**閱讀檢查**：把他的反問全部拿掉後，對話裡是否只剩別人在提供時間、善意與關心，他只接收結果。如果是，那就不是反駁型人格被修好，而是人與人的回合被修掉了。此時依第 40 條以閱讀體驗優先，再用第 2、31、34、35 條檢查新句有沒有說白潛台詞、事後說理、補辦事流程或替行為命名，**不反過來用這些條目否決一句基本的人性回應**。

這一條原本的執行方式造成全書性的過度矯正，經過見文末附錄。作者裁定全部採用，隨後在校閱時改寫或退回 5 處，最終留下 16 處，並給出三條校準：

- **一次性的服務往來不補道謝或道歉**：碼頭人員提醒他不要擋出口、醫生講完檢查結果，補一句反而是禮貌表演。他們把事情做完就離場，動作接得住就夠
- **朋友的關心可以用動作接住**：第十一章他正在消化分手、被問要不要去朋友家睡，作者把「好，我會回有沒有吃，謝謝你」還原成「我笑不太出來，還是點了頭」。那正是上述沉默的第一種情況，補話會把他修得太完整
- **道謝用最簡單的說法**：「謝謝你的幫忙」勝過「謝謝你先幫我說」，也不要「謝了」這種口頭語

問題從來不是他不夠客氣，是別人給了東西他沒有接住。接住可以是一句最簡單的謝謝，也可以是一個動作

38. **保留有根的隱喻**：作者明確表示喜歡隱喻；「不要刻意」「去除 AI 味」不等於只用直白陳述。書名與篇章名優先從既有生命素材、原始敘述與作品中找能承載感受及變化的意象，讓理解隨閱讀形成，不要求標題先解釋主題，也不為候選名字反向加戲。共用原則同步於 `rui-xuan-book-v2` skill「比喻」一節。2026-09-29 新第六章作者退回只把孤島、浮木寫進正文的補法，最後採納營區疏離、返家仍無法休息、拖到最後回營及她聽他說與「有我在」的互動。指定意象也可能是在要求閱讀感受；先讓處境與回應成立，再決定是否寫出比喻，不把意象詞出現視為完成，也不因此禁用隱喻

39. **理解句要有說話的時間與主體，不寫成無主的格言**：第十三章作者把「想有人一起，和今天幾點回家，原來可以是兩件事」改成「這時候才發現想有人一起，和今天幾點回家，其實是兩件事」，也把「真正讓我停下來的，是我常把還沒說出口的未來先放到今天前面」改成「這時才意識到，原來我過去總是把還沒說出口的未來先放到眼前」。兩處都不是刪掉理解，而是把它放回人物當下的意識。判準是：**這句話是誰、在什麼時候發現的**；無主的判斷句讀起來像格言或作者插話，補上「這時候才發現」「這時才意識到」就回到故事時間。與第 26、31 條並用——能由動作承擔的理解仍然刪掉，留下來的那幾句要有主體。同輪作者也把判決語與分析語改成日常說法：「那些記得的事不必被判成錯」改為「那些記得的事沒有對或錯」，「只是那些靠近不能替現在作答」改為「我們都在用自己的方式靠近彼此，卻忘了開口確認方向」；後者把抽象的否定換成兩人各自做過的事

40. **閱讀體驗優先於規則與清單**：作者 2026-09-22 明確說「閱讀體驗才是最重要的」，2026-09-23 進一步取消「手改句一律不動」。手改與偏好是高價值證據，**不是用來擋本輪必要修改的禁令**；若動到可確認的手改句，留下逐字前後對照和理由，交作者校閱。後記那一輪連續三次拉扯都出於此：Claude 以「這句在保護清單裡」為由不動一個讀者與編輯都點名的心理語彙（「身體總是比較先知道」，且該句本來就不是作者手改的），又因為只回復單句而留下失去對照端的「也不能反過來」，還把 v1 的反轉句與它的定義句緊貼在一起，讓反轉被自己解釋掉。判準是整段讀起來順不順，條目其次。**作者親筆樣本只放能核實的句子，不放 Claude 自己寫的句子。**

作者同一輪的手改也給出具體做法：

- **密集的判斷段拆成一句一段**：「我後來才比較能看清的兩件事：」領起，兩項各自成段，讀起來有呼吸；不把四個短判斷擠成一段
- **不寫成他擋著對方，寫成他沒有開口**：「沒有讓她參與」改「沒有邀請她參與」，「共同生活裡沒談清楚的安排，要讓對方也在場」改「共同生活裡的安排，要邀請對方也在場」
- **不替自己的行為下判決**：「要對方退讓」改「照著沒有說好的方向前進」
- **為回應讀者顧慮而加的條款式補丁整句拿掉**：「額外的付出可以出於喜歡」之後不再補條件，顧慮由後文自然承接
- **隱喻不要解釋成機制**：「慢慢代謝掉的」一度被擴寫成「大腦透過新陳代謝讓這些經驗變成養分，幫助我吸收與成長」，既是錯的機制主張，也把身體感換成三個抽象詞；收回原句
- **成語會把意思拐回去**：「反求諸己」的傳統用法是檢討自己，放在講內耗的段落會讀成「要更努力檢討自己」，改成「只要答案得由別人給，那份清單就不會有完成的一天」

## 作者人工潤稿與定稿確認

這是三個不同階段，不因章節已寫完、作者說「看完了／改完了／改好了」，就跳到定稿：

1. **潤稿中**：讀現稿及相關 diff，理解作者親手改動的用意；作者指出不順、怪異或因果不成立時，結合上下文協助修改。暫記本輪的來源、取捨與候選原則，區分作者親筆、作者採納與模型提議；尚未核准的內容不寫成正式偏好或定稿紀錄。
2. **作者說「第 N 章看完了／改完了／改好了」**：通讀該章現稿並對照本輪 diff，辨認作者改動的意圖，客觀列出有效與有疑慮的改動，指出閱讀問題並給具體建議。只有不同修法會實質改變人物、事件或章節效果，且需要作者選擇時，才列不同方向、取捨與推薦；不為每個疑點湊兩個版本。單說「看完了」是整章評讀，不代表授權直改、接受建議、同意定稿或 commit；若同時請求修稿，就在可確認的範圍內直接修改，正文仍留在工作區交作者校閱。
3. **作者明確說「這章 OK／可以定稿／同意提交」**：才執行下方七步，把已確認的手改與取捨正式迭代進紀錄並精準提交。若同時說「先不要提交」，保留工作區並只做已獲准的非提交事項；語意不明時詢問，不推定授權。「這句可以」「這幾處照改」只核准局部修改，不代表整章定稿。

### 作者確認這章 OK 後的七步

1. **核對定稿**：整章讀過並對照本輪修改，確認採納項目已套用、動到的作者手改句已記錄前後差異與理由、刪改處銜接正常。不自行再潤稿，也不重跑寫作流水線；若有實質矛盾，列出具體位置與影響，交作者決定後再提交。
2. **同步事實**：若修稿改動時間、人物、物件、約定或資訊邊界，同步本章相關的 `_continuity.md`、場景表或章卡。歷史回饋保留原貌，必要時附上本輪處理結果，不把舊問題寫成仍待處理。
3. **迭代修稿偏好**：回看本輪作者手改與明確採納的取捨，辨認可供後續章節使用的原則，更新本文件「使用者修稿偏好」。已有相同規則就補充或合併，附必要的前後例子；單一場景的選擇留在該章紀錄，不升格成全書禁令。沒有新原則時不硬加條目。只有涉及跨文體的共用聲音規則時，才同步 `rui-xuan-book-v2` skill。
4. **更新手改資訊**：核對本輪真正由作者親筆修改、親自採納及模型提議但尚未核准的句子，更新 `_feedback/全書-手改對照.md` 與本輪紀錄；`_feedback/全書-作者手改句.md` 僅作 Git 候選快照，檢查首次入庫污染，不當成保護清單。
5. **更新進度**：依既定算法重算字數，在交接文件及相關章節紀錄標示校閱狀態、已處理事項與後續承接事項；不能因正文檔已存在就視為定稿。
6. **精準提交**：逐一指定本章正文、相關回饋及本輪文件；共用檔案若混有其他未核准章節的修改，只暫存本章相關部分。核對 staged diff，不使用 `git add -A`。只有 commit 確實含作者親筆修稿時，主旨才包含 `hand edit`；不得夾帶其他尚未校閱的章節。
7. **回報**：提供 commit 結果、定稿字數及本輪新增或補充的修稿原則；有尚未解決的項目則如實列出，不宣稱整章已完成。

## Commit 規則

- **書稿內容等作者明確確認整章 OK 才 commit**：章節正文、該章回饋檔與 `_continuity.md`，跑完流程、Claude 讀過並修正後，先留在工作區，交給作者人工校閱；「看完了／改完了／改好了」只啟動整章評讀，不是提交許可
- 作者校閱時若有親筆手改一起放進這次 commit，訊息可寫成 `Apply the author's hand edits and approve …`；若僅核准模型草稿，不使用 `hand edit` 誤標來源。腳本抽出的加號只作候選，仍須逐句核實
- 等待校閱期間，同一章不再跑新的 Codex 步驟，免得覆蓋作者的手改
- 流程腳本、文件與規格（`docs/`、skill）的調整照常直接 commit
- 回饋檔與 `_continuity.md` 照常隨流程更新

## 為什麼加入場景表與稽核

第六章完成後，使用者讀出八處前後矛盾：豪華露營後段變成自己煮鍋、在帳篷外刷牙；她知道他沒說出口的流星願望；合照明明是她的手機拍的，卻要他傳原檔；外套隔天還在滴水；對白笑點接不上；坐在駕駛座替副駕開門。追查結果：

1. 其中六處出自寫作初稿。一次寫近萬字時，細節是依類型預設當場生成的；提高字數與細節要求後，錯誤機會跟著增加，卻沒有對應的核對
2. 兩處出自潤飾新寫的場景，只接好相鄰段落，沒有回查全章相關物件
3. 讀者步驟以第一次讀的人回應，看不見資訊邊界越界；編輯步驟的注意力在結構，沒有逐行核對事實
4. `_continuity.md` 只記發生的事，沒記誰不知道什麼
5. commit 前的人工檢查只核對章卡事件是否出現，沒有整章讀過

因此加入寫作前的場景表、潤飾新增場景前的回查、獨立的稽核步驟、連續性的資訊邊界，以及 commit 前整章閱讀。

## 附錄：條文的由來與量化背景

### 第 34 條｜關係越好，嬉鬧越少

笑鬧戲謔類用詞每千字：曖昧期的第一章 4.1、第三章 3.3、第六章 2.5，而關係最好的第七章只有 1.4、修復期的第九章 0.9、含生日花燈流星螢火蟲的第五章只有 0.57，比爭執的第八章還低。第七章同居段三十四句對白裡只有四句在玩，其餘全是行李箱放哪、房租誰付、備忘錄欄位、誰洗衣服。**關係越好，嬉鬧越少**，這是規則疊加的結果，不是人物。逐處掃描見 `_feedback/全書-親密對話.md`。

### 第 37 條｜愛理不理是怎麼長出來的

作者 2026-09-22 表示「很看不爽男主愛理不理的態度」。查證後全書八萬五千字裡他說謝謝或麻煩你原本只有六次，單音節回覆十九處，而 `is-me/` 的素材裡他渴望被需要與被重視、在意別人怎麼看他、和一桌陌生人吃一頓飯會開始相信人有善意。也就是說那不是人物，是第 37 條把「不推回去」執行成「一律收短」，加上第 2、31、34 條各自把道謝、當場回應與待人的動作當成可刪的東西。逐處清單與「該留」的十二處見 `_feedback/全書-對人的態度.md`。
